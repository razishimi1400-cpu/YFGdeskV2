# YFGDESK v2 — نسخهٔ نصبی ویندوز (با سرورهای تعبیه‌شده)

## ویژگیٔ جدید این نسخه

آدرس سه سرور تولیدی به‌صورت **رمزنگاری‌شده (XOR + Base64)** درون باینری کلاینت تعبیه شده است:

| سرور | آدرس | نقش |
|------|------|-----|
| ۱ | `188.121.147.94:7070` | primary |
| ۲ | `37.114.216.224:7070` | fallback ۱ |
| ۳ | `94.182.31.149:7070` | fallback ۲ |

### مزایا

- ✅ **آدرس سرورها در باینری قابل دیدن نیست** — با `strings` یا hex editor ساده قابل استخراج نیست
- ✅ **Failover خودکار** — اگر سرور اول قطع شد، کلاینت خودکار به سرور بعدی وصل می‌شود
- ✅ **بدون نیاز به تنظیمات دستی** — کاربر فقط `.exe` را اجرا می‌کند
- ✅ **تلاش مجدد با backoff** — ۳ بار تلاش روی هر سرور، سپس انتقال به سرور بعدی

### نحوهٔ کار

```
۱. کلاینت باز می‌شود
۲. در صورت نبود identity محلی، enrollWithFailover شروع می‌شود:
   - سرور ۱ را امتحان کن → اگر OK، همان را به‌عنوان active ذخیره کن
   - اگر fail کرد → سرور ۲ → اگر OK، همان
   - اگر fail کرد → سرور ۳ → اگر OK، همان
   - اگر همه fail کردند → پیام «هویت در دسترس نیست» نمایش بده
۳. پس از اتصال موفق، signaling socket به همان سرور وصل می‌شود
۴. اگر اتصال signaling قطع شد:
   - ۳ بار تلاش مجدد با backoff (1s, 2s, 4s)
   - اگر باز هم ناموفق بود → سرور بعدی در لیست امتحان شود
   - چرخه ادامه می‌یابد تا اتصال برقرار شود
```

## استقرار سرور روی VPS

سرورهای تولیدی باید روی VPS یا سرور اختصاصی اجرا شوند. برای هر کدام:

```bash
# روی VPS لینوکسی (مثلاً Ubuntu 22.04+)
git clone https://github.com/razishimi1400-cpu/YFGdeskV2.git
cd YFGdeskV2

# Build سرور
dotnet publish server/YfgDesk.Server.csproj -c Release -r linux-x64 --self-contained true -o ./publish/server

# اجرا
cd publish/server
YFGDESK_DB="Data Source=/var/lib/yfgdesk/yfgdesk.db" \
YFGDESK_TOKEN_SECRET="<base64 حداقل ۳۲ بایت>" \
YFGDESK_TURN_URLS="turn:188.121.147.94:3478?transport=udp,turn:188.121.147.94:3478?transport=tcp" \
YFGDESK_TURN_SHARED_SECRET="<64 hex>" \
YFGDESK_TURN_REALM="yfgdesk.example.com" \
ASPNETCORE_URLS="http://0.0.0.0:7070" \
./YfgDesk.Server
```

برای اجرای دائمی، از `systemd` یا `supervisor` استفاده کنید.

## امنیت سرورهای تعبیه‌شده

آدرس سرورها با XOR + Base64 رمزنگاری شده‌اند. این **رمزنگاری واقعی نیست** — یک مکانیزم مبهم‌سازی (obfuscation) است که جلوی استخراج ساده با `strings` یا hex editor را می‌گیرد. یک مهاجم مصمم می‌تواند با decompile کردن باینری و اجرای متد `Decode`، آدرس‌ها را استخراج کند.

برای محافظت واقعی در production:
- از AES-GCM با کلید مشتق‌شده از DPAPI ویندوز استفاده کنید
- یا آدرس سرور را در زمان نصب از کاربر بگیرید و در DPAPI ذخیره کنید

## رفع خطا

### «اتصال برقرار نشد» یا «همهٔ سرورها ناموفق بودند»

- بررسی کنید اینترنت در دسترس است
- بررسی کنید که سرورهای تولیدی بالا هستند (می‌توانید با `curl http://188.121.147.94:7070/api/health` تست کنید)
- فایروال ممکن است پورت 7070 را بسته باشد

### Override سرور (برای توسعه)

اگر می‌خواهید به سرور محلی خودتان وصل شوید:

```cmd
set YFGDESK_SERVER_URL=http://localhost:6215
scripts\run-client.bat
```
